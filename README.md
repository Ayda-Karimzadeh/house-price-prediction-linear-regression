# California Housing Price Prediction

A machine learning project to predict median house values across California districts using demographic and housing data from the 1990 U.S. Census.

## Overview

This project builds an end-to-end regression pipeline — from business understanding through model evaluation — to predict `median_house_value` based on features like location, housing supply, population density, and median income.

Because the underlying data is from 1990, the resulting model is not intended for real-time, market-accurate price estimates. Instead, the project serves as a methodological foundation: the same pipeline (data preparation, feature engineering, model selection, evaluation) is designed to be reapplied later to current, live housing data as part of a broader real-estate pricing platform.

## Dataset

[California Housing Prices](https://www.kaggle.com/datasets/camnugent/california-housing-prices) (Kaggle) — median house prices for California districts, derived from the 1990 census. 20,640 records, 10 columns (9 numerical, 1 categorical: `ocean_proximity`).

**Known limitations**

- `median_house_value` is capped at 500,001 (965 records, ~4.7%) and `housing_median_age` is capped at 52 (1,273 records, ~6.2%).
- Data is aggregated at the district level, not the individual property level.
- It is a single historical snapshot, not representative of current prices.

## Workflow

1. **Business Understanding** — problem definition, objectives, success criteria
2. **Data Understanding** — structure, data types, missing values, duplicates, outliers, distributions, correlations, geographic view
3. **Data Preparation** — train/test split, feature engineering, preprocessing pipeline (imputation, scaling, encoding)
4. **Modeling** — baseline Linear Regression
5. **Evaluation** — MAE, RMSE and R² on the held-out test set

## How to Run

```bash
pip install -r requirements.txt
jupyter notebook
```

Run the notebooks **in order, from `01` to `05`**. The `artifacts/` folder (at the project root, next to `notebooks/`) is created automatically when you run the notebooks:

- `03_data_preparation.ipynb` saves the prepared train/test data and the fitted preprocessor to `artifacts/`.
- `04_modeling.ipynb` loads those files, trains the model, and saves the predictions and the model.
- `05_evaluation.ipynb` loads the predictions and computes the metrics.

Skipping `03` will cause `04` to fail unless the `artifacts/` files already exist.
